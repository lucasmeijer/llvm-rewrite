# The corpus has almost no real debug info, so debug-info bugs only show up through debugify or private clang builds

- **Date / implementation / unit:** 2026-11-14 / jai / L1.extra.assignment-tracking (+ unowned default<O2> loud failures)
- **What happened:** Only 124 corpus files contain `#dbg_declare`, none of them real clang `-O2 -g` output, and no
  corpus file had assignment tracking except the 63 LLVM tests I imported. To exercise `#dbg_assign` beyond those I
  compiled tests/e2e/src with `clang -O2 -g -gno-key-instructions -Xclang -disable-llvm-passes` into a scratch
  `tests/zz_dbgat/` directory and swept `declare-to-assign,<pass>` over it (`--all-files` plus a glob). Two traps:
  (1) any `.ll` under `tests/` is picked up by `check`, so a `check --update` run while the scratch directory existed
  added 221 lines to passing.txt (caught and removed before committing; the directory now lives in /tmp and is moved
  in only for sweeps); (2) clang 23 emits key-instruction atoms by default, which jai rejects loudly in several
  passes, hiding everything else until `-gno-key-instructions`.
  The `debugify,<pass>` sweeps also turned up a large pre-existing class of silent bugs unrelated to assignment
  tracking: the plain `replace_all_uses_with` / `erase_inst` did not update debug records, so every pass that forgot
  the `_with_metadata` variant left `<badref>` records (13 bad-ir and ~100 differs in `debugify,default<O2>`). Nobody
  had swept `debugify,default<O2>` or `debugify,cgscc(inline)` before.
- **Time or effort lost:** ~30 min on the scratch-corpus setup and the passing.txt cleanup; the debugify findings
  were a useful detour (~1.5 h) but widened the task.
- **What would have helped:** a harness option to sweep files outside `tests/` (e.g. `--files <dir>`) so generated
  inputs never touch the ratchet; a committed `-g` corpus (clang `-O2 -g` builds of tests/e2e/src, regenerated by the
  harness like the O0/O2 directories) so debug-info paths are covered by the ordinary sweeps; and `debugify,default<O2>`
  in the standard sweep list of the port-pass skill.
- **What you did instead:** scratch directory moved in and out of `tests/` around sweeps; made the core RAUW/erase
  functions do the ValueAsMetadata update (as LLVM's Value does), which removed the whole badref class.
  `debugify,default<O2>` still has 82 differs (not triaged).
